SECURITY / TRANSPARENCY

Security at EXEcify.

A factual overview of how EXEcify processes uploaded projects, protects temporary build data and communicates known limitations.

Important: EXEcify is still under development. The controls below reduce some risks, but they cannot make untrusted code safe or guarantee that a generated EXE is harmless.

Upload and build flow

  • The website uses HTTPS.
  • Cloudflare Workers handles uploads. Encrypted file chunks are stored temporarily in Workers KV.
  • GitHub Actions runs builds on temporary Windows runners with the required build tools.
  • Builds have time limits. Uploads and ZIP archives are checked for size and unsafe paths.

Storage and deletion

EXEcify encrypts uploaded file contents and build output with AES-256-GCM before storing them in Workers KV. Source chunks are deleted when a build finishes or fails. Output chunks are deleted after download. A 24-hour expiry acts as a fallback if cleanup does not run. Cloudflare and GitHub may keep operational records under their own retention policies.

Known limitations

Uploaded projects and build scripts can contain unsafe code. Each build currently runs on a general-purpose GitHub-hosted Windows runner, not in a separate micro-VM. Network access is also available because builds may need to download dependencies. Do not upload confidential projects, personal data, passwords, API keys or private keys.

EXEcify does not digitally sign generated EXEs. Windows Defender, SmartScreen or another antivirus product may warn about files that are new or unsigned. EXEcify does not disable or bypass those warnings.

Security review

A preliminary static review of selected backend code is available on GitHub. AI assistance was used during the review. It was not an independent security audit, penetration test or certification. The report lists findings and areas that still need review.

Report a security issue

If you believe you have found a security issue, please report it privately through the contact page. Avoid posting exploit details publicly before the issue has been reviewed.

Operational checks

The service status page runs a live check against the public Worker health endpoint. It confirms that the Worker responds and can read from its Workers KV binding. It does not test GitHub Actions dispatch, runner availability, compiler toolchains or individual language builds.

Security improvements in progress

EXEcify checks uploads, encrypts stored file chunks, limits build time and removes temporary data. However, user-supplied code still runs on a general-purpose hosted Windows runner. There is no dedicated sandbox for each build. Do not use EXEcify for confidential or sensitive projects.

GitHub Actions checks the website files, sitemap and homepage structured data when changes are pushed or submitted as a pull request. These checks do not test the security of the build system.
