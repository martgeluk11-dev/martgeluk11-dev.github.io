Documentation.

How to prepare a project, choose its entry file and understand the output EXEcify creates.

Supported project types

JavaScript / Node.jsNode projects using package.json.

C / C++CMake projects or supported simple source projects.
C# / .NET.NET projects using project files and NuGet restore.
GoGo projects using go.mod or supported source entry points.
RustCargo projects using Cargo.toml.
JavaJava projects using supported source/build layouts.

Prepare your project

  1. Put the source files, assets and dependency files in the same project folder.
  2. If your project uses dependencies, include its manifest, such as requirements.txt, package.json, go.mod, Cargo.toml or a .NET project file.
  3. When asked, select the correct entry file. If the project uses a build manifest, include it in the upload.
  4. Remove generated folders, caches and files that the app does not use.

Build limits

  • Maximum 150 files per project.
  • Maximum total input size: 80 MB.
  • Maximum generated output size: 80 MB.
  • Build jobs have a time limit and may fail if dependencies cannot be installed or the project needs unsupported native components.

These are the current upload and output limits. If a build fails, read the error message and check whether the project builds with its usual development tools.

Output and Windows warnings

EXEcify creates Windows build output; it does not certify that the uploaded code or generated executable is safe. EXEcify does not currently digitally sign generated executables. Windows Defender or SmartScreen may show warnings for unsigned or unfamiliar files.

Use the SHA-256 checksum shown after a successful download to identify the exact file. A matching checksum proves file integrity relative to that checksum; it does not prove that a file is harmless.

Privacy and security

Do not upload confidential information. Never include passwords, API keys, private keys, personal data or files you are not comfortable sharing with EXEcify and its service providers.

Read the privacy information and Security Center before uploading. Temporary build data is processed by third-party infrastructure providers as described on those pages.

Troubleshooting

  • Entry file error: make sure the selected entry file exists in the uploaded project and matches the chosen language.
  • Missing dependency: include the project's dependency manifest and ensure package versions are compatible with the build environment.
  • Build timeout: try removing unused dependencies and generated files. Very large or complex projects may exceed the time limit.
  • Unsupported project: native modules, platform-specific dependencies and unusual build systems may not be supported.

If you need help, visit the contact page. Include the language and error message, but never send secrets or private source files in a public issue.
